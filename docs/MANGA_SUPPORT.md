# 漫画阅读（Mac / iOS）

macOS / iOS 1.4.0 已包含漫画阅读。Windows 1.3.0 暂未实现漫画阅读。

点击添加网址，粘贴漫画章节或目录链接。Mac / iOS 都可选择 **自动识别（默认）／文字小说／漫画**。自动模式保持专用适配器优先，通用小说未取得可信正文时，再尝试高置信度的通用漫画识别；小说模式只解析文字正文；漫画模式先走专用适配，不匹配的站点使用通用漫画解析。

选择会保存到本机书籍，后续章节、目录刷新、预取、离线下载和重新打开都会沿用。旧书默认自动识别。书架点击书籍直接恢复阅读位置，目录从阅读菜单打开。

通用漫画解析从图片节点的局部祖先发现候选正文区域，不再要求固定容器名。按 DOM 顺序读取普通与懒加载图片，过滤广告、Logo、封面缩略图、占位图及重复地址，再用图片序列和章节上下文评分。不会把整个网页的图片都当正文；证据不足或候选区域有歧义时会报错。目录保持网站 DOM 顺序，漫画翻话优先使用页面明确给出的上下话链接。

- **上下滚动**：图片按章节顺序排列，滑到章末可进入下一话。
- **左右翻页**：每张图片是一页，左右滑动或点击翻页按钮；Mac 也支持左右方向键。两端均在阅读设置中切换。Mac 与 iPad 提供自动 / 单页 / 双页；iPad 默认开启「横屏自动双页」，横屏宽视口临时使用左右翻页与双页布局；回到竖屏或窄视口、或关闭开关后，恢复保存的阅读方式和布局，不改写用户偏好。首图可单页、横图独占，组合不跨章；旋转和布局切换不改写原始图片索引。
- **预取**：Mac 与 iOS 默认开启预取。小说最多预取 3 章；漫画最多提前缓存 10 张图片，可跨章节补齐窗口，不等待整本下载；可在设置中关闭。
- **进度恢复**：保存当前图片页码，书架与阅读进度同步沿用已有协议；同步不传输图片。
- **离线阅读**：看过的图片留在本机。选择“缓存当前章 / 后续章节 / 全书”会下载对应章节图片。只有整章图片下载完成后才标记“可离线阅读”。

每本漫画的图片磁盘缓存预算为 512 MB。退出阅读或切换书籍时，超过预算就从最早读过的章节开始清理；保留当前章和未读的预取图片。主动下载的未读章节不受自动清理影响，因此这些受保护内容本身超过预算时不会强行删除。书籍信息、目录与阅读位置始终保留。

## 本地缓存管理

Mac 设置的“缓存”页、iOS 设置的“本地缓存管理”可查看总大小与每本书的占用，支持清空全部或单独清理一本漫画 / 网页小说。保留书架、目录、阅读位置和本地 TXT。清理正在阅读的书会返回书架，避免清空后自动重新下载。

图片按磁盘文件大小统计，正文按 UTF-8 内容大小统计；数据库元数据和系统网页验证缓存另行管理。删除正文后数据库空间可供后续内容复用，统计不等同于 SQLite 文件本身的大小。

## 通用漫画识别与评分

`MangaRegionScorer` 只处理当前 HTML，不请求图片、不解码位图，也不扫描后续章节。一次遍历收集图片及文字/链接统计，每张图片向上检查最多 8 层局部容器，排除 `body` / `html`；候选区域复用图片索引。网页脚本已加载图片时，快照记录自然尺寸；识别到正文区域的 `blob:` 图片时，可按需读取网页正常显示的图片，详见下节；不猜测下载地址，不手动解密或绕过访问限制。宽度一致性只提供少量加分，横向跨页图、尺寸不同的页面与单张超长条漫都可以成立。

正向指标合计最高 100 分，以下均为证据分，不是统计概率：

| 指标 | 权重 | 规则 |
| --- | ---: | --- |
| 图片序列长度 | 20 | 至少 8 张得 20 分，4～7 张 16 分，2～3 张 10 分；有尺寸证据的单张长图 14 分，普通单张 10 分。 |
| DOM 连续性 | 12 | 相邻有效图片之间没有长文字（单节点至少 30 字）或带文字的非图片节点链接，按连续相邻对占比计分。每页的 `figure` / `picture` 包装不打断序列。 |
| 共同父级 | 8 | 共享同一父级的最大图片组占比；最多折叠 3 层无文字、单子节点的页包装。 |
| 有效大图比例 | 12 | 宽至少 400、高至少 300 的有效图片数 ÷ 候选图片总数；未知尺寸不当作大图。 |
| 宽高比 | 4 | 已知尺寸中，高/宽至少 0.35 的比例；不设置高度上限，允许超长条漫。 |
| 宽度接近 | 4 | 已知宽度中，落在中位宽度 ±25% 的比例；至少两张才计分，尺寸不同不直接拒绝。 |
| 少文字 | 15 | 非链接文字最多 40 字得 15 分，最多 120 字 10 分，少于 240 字 3 分。 |
| 阅读容器语义 | 10 | reader / manga / comic 等名称或 `data-reader-images`，仅作为加分，不作为必需条件。 |
| 章节标题 | 5 | 第 N 话/章、chapter/episode、数字章节标题等。 |
| 上下话导航 | 10 | 存在同源上一话/下一话链接；“下一页”单独视为分页，不作为下一话证据。 |

扣分与拒绝条件：图片链接到其他作品或页面按比例扣最多 35 分；链接文字占比高再扣 20 分，链接数量超过图片数两倍（最低 4 条）再扣 10 分；非链接文字超过 120 字扣 15 分，达到 240 字拒绝该区域；过滤掉的杂图占比最多扣 3 分，重复地址不算杂图。多个各含至少两张图的独立子区域不拼接；两个不重叠区域分差不超过 5 分时，拒绝自动选取，避免随机导入。

**手动漫画模式**最低 55 分，仍需章节或阅读区域证据。单张图片额外要求明确大图尺寸、章节证据及阅读区域语义或长条特征。**自动模式**最低 80 分，并要求上下话导航或“阅读区域语义 + 章节标题”；通常至少三张，单张超长图必须有上下话导航。普通单张和短序列可供明确选择“漫画”的用户导入，但不会因此自动把插图识别成漫画。

自动路由仍先选择专用适配器；通用小说正文需至少 60 字非链接文字，链接文字不超过候选文字的四分之一。正文不可信时才尝试通用漫画；带明确漫画元数据或页面标题的目录使用漫画章节列表规则，接受数字及特殊篇名，不让小说章节号规则截断目录；两者证据都不足会报错。漫画识别失败后的小说兜底仅放宽导航链接占比，仍要求至少 60 字非链接内容；图片加载进度、失败和等待提示先移除，不作为正文。取消会继续向上传播，不被漫画兜底吞掉。

Windows 接入时可复用本表和 `GenericMangaRecognitionTests` 的自造 HTML 思路，保持 DOM 顺序与原始章节 URL，不需要改变同步 schema、安装第三方解析运行环境或加入站点分支。

## 通用 blob 图片读取

`blob:` 是当前网页中的临时图片地址，不能直接作为持久化下载链接。通用机制在正文区域评分通过、且至少一张图片确实使用同源 `blob:` 时启用；同区域尚未加载的图片保留原始位置。书籍保存 `yyreader-blob://image` 地址，内容是章节 URL 与图片索引，不保存会失效的 blob UUID。普通 HTTP 图片继续使用原下载路径。

首次读取未缓存图片时复用现有 WebKit 会话，让网站正常脚本加载这一页，再读取该页已经显示的图片。重新打开会按通用评分重新定位正文区域，以原始索引和当前节点身份定位；懒加载替换节点时仅重新绑定一次，并检查图片数量、章节和请求身份。旧请求或取消不会覆盖新页面。缓存命中和离线阅读直接使用原图磁盘缓存与缩略图缓存，不打开网页。

每次只传递一张图片，单张上限 30 MB，不把整章图片转换为 base64；预取仍最多 10 张，磁盘预算仍为每本 512 MB。切换站点后释放其他站点空闲的漫画图片会话，不为每张图片创建浏览器。首次未缓存的读取需要网站加载时间，网页自身的图片加载也会占用内存，因此不能承诺与普通 HTTP 图片完全相同的开销。

此入口不按站点白名单启用，适用于能通过正文评分、以正常 DOM 图片节点显示 blob 的页面。只有 canvas、跨域 iframe、需要登录或验证的内容，以及无法稳定恢复图片序列的虚拟化阅读器，不保证可用。多看漫画另保留专用适配器，利用网站公开章节列表取得完整目录；通用入口也可独立识别它的图片区域。

Windows 交接：沿用上述章节 URL + 原始图片索引的稳定键，在正常网页会话内重新定位正文区域并按需读单张已显示图片，接入本端原图缓存。不要把临时 blob 地址作为下载链接，也无需修改同步协议。

## 实现与后续交接

Mac 与 iOS 共用 `GuaziMangaAdapter`、`ZaiMangaAdapter`、`HaoduoMangaAdapter`、`ManhuazhanMangaAdapter`、`DuokanMangaAdapter`、`GenericMangaAdapter`、`MangaImageCache` 和 `MangaReaderView`。适配器沿用 `NovelSourceAdapter` 接口，解析结果增加 `imageURLs`，小说调用默认传空数组。

`Book.importContentType` 保存用户选择的 `auto / novel / manga`，`resolvedContentType` 记录实际解析结果；两字段均有 `auto` 默认值，供 SwiftData 对旧数据库自动迁移。章节是否有缓存仍以实际文字或图片列表判断，不能因用户选择“漫画”就标成已缓存。重新选择类型导入同一本书后，不符合该类型的旧章节缓存会重新加载，解析失败不覆盖旧内容。

这两个类型字段是本机偏好，不加入同步或书架传输协议。Windows 若接入内容类型选择，可沿用三个字符串值和解析路由；无需为此更改共享快照 schema。

SwiftData 的 `Chapter` 增加 `imageSourceURLs`（默认空数组）与 `imagesCachedAt`（可为空），兼容已有小说记录。`isCached` 表示已取得文字或漫画图片列表；漫画的 `isAvailableOffline` 另外要求图片下载完成。后台下载与清理缓存均维护这些字段。

图片下载串行、限速、可取消；HTTP 429 按 `Retry-After` 暂停请求，不自动紧密重试。下载队列空闲后释放最后一个任务的原图引用；章节首次打开读取缓存尺寸，之后每轮预取只补充本轮尚未知的图片尺寸，避免重复扫描整章。原图存放在应用支持目录的 `YYReader/MangaImages` 下，以完整图片 URL 的 SHA-256 作为文件名。解码与缩略图生成在 actor 内执行，阅读器只保留可见区域的图片。加载失败显示重试入口。

漫画不进入文字分页器，也不拼接其他章节正文。页面使用 SwiftUI `Image`、`ScrollView` 与 `LazyVStack`。iOS 左右翻页只渲染当前组与相邻两组，双页最多 6 张；点击或滑动按整组翻页，双击放大所点图片，iPhone 保持单页。好多漫使用现有 WebKit 流程执行公开网页脚本，仅提取图片地址；不使用 WebKit 显示漫画，不绕过网站访问限制。

Windows 若增加此功能，需要扩展本地章节模型和解析结果、图片磁盘缓存及原生阅读视图。现有同步快照只交换书籍信息与阅读位置，不需要把图片地址或图片数据加入快照；`paragraphIndex` 在漫画中对应图片索引。

## 最小检查

`GenericMangaRecognitionTests` 覆盖陌生容器、序列连续性、大图比例、嵌套页包装、尺寸混合、单张长图、噪声过滤、图集/推荐卡片拒绝、歧义区域、自动路由与导入。`MangaParserTests` 使用自造 HTML / JSON 和一像素 PNG，覆盖图片顺序、广告排除、带查询参数的章节身份、完整目录、分组次序、手机域名、图片解码、缓存清理及 SwiftData 持久化。`GenericBlobMangaTests` 与 `DuokanMangaTests` 补充稳定图片身份、懒加载位置、外部广告节点、来源校验、按需读取、缓存命中、离线重开和取消回归。测试不依赖实时网站。

人工检查：在两端打开上述任一示例，切换两种阅读方式，前后切换章节，再返回书架重新打开，确认恢复到同一图片；缓存当前章后断网检查图片是否可读。
