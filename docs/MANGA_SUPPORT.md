# 漫画阅读（Mac / iOS）

当前源码已支持漫画，现有 GitHub 安装包尚未包含此功能。Windows 暂未实现漫画阅读。

点击添加网址，粘贴漫画章节或目录链接。导入后从书架打开，选择要阅读的章节即可。

- **上下滚动**：图片按章节顺序排列，滑到章末可进入下一话。
- **左右翻页**：每张图片是一页，左右滑动或点击翻页按钮；Mac 也支持左右方向键。Mac 在漫画顶部切换阅读方式，iOS 在阅读设置中切换。
- **预取**：Mac 与 iOS 默认开启预取。小说最多预取 3 章；漫画最多提前缓存 10 张图片，可跨章节补齐窗口，不等待整本下载；可在设置中关闭。
- **进度恢复**：保存当前图片页码，书架与阅读进度同步沿用已有协议；同步不传输图片。
- **离线阅读**：看过的图片留在本机。选择“缓存当前章 / 后续章节 / 全书”会下载对应章节图片。只有整章图片下载完成后才标记“可离线阅读”。

每本漫画的图片磁盘缓存预算为 512 MB。退出阅读或切换书籍时，超过预算就从最早读过的章节开始清理；保留当前章和未读的预取图片。主动下载的未读章节不受自动清理影响，因此这些受保护内容本身超过预算时不会强行删除。书籍信息、目录与阅读位置始终保留。

## 本地缓存管理

Mac 设置的“缓存”页、iOS 设置的“本地缓存管理”可查看总大小与每本书的占用，支持清空全部或单独清理一本漫画 / 网页小说。保留书架、目录、阅读位置和本地 TXT。清理正在阅读的书会返回书架，避免清空后自动重新下载。

图片按磁盘文件大小统计，正文按 UTF-8 内容大小统计；数据库元数据和系统网页验证缓存另行管理。删除正文后数据库空间可供后续内容复用，统计不等同于 SQLite 文件本身的大小。

## 实现与后续交接

Mac 与 iOS 共用 `GuaziMangaAdapter`、`ZaiMangaAdapter`、`HaoduoMangaAdapter`、`MangaImageCache` 和 `MangaReaderView`。适配器沿用 `NovelSourceAdapter` 接口，解析结果增加 `imageURLs`，小说调用默认传空数组。

SwiftData 的 `Chapter` 增加 `imageSourceURLs`（默认空数组）与 `imagesCachedAt`（可为空），兼容已有小说记录。`isCached` 表示已取得文字或漫画图片列表；漫画的 `isAvailableOffline` 另外要求图片下载完成。后台下载与清理缓存均维护这些字段。

图片下载串行、限速、可取消；HTTP 429 按 `Retry-After` 暂停请求，不自动紧密重试。原图存放在应用支持目录的 `YYReader/MangaImages` 下，以完整图片 URL 的 SHA-256 作为文件名。解码与缩略图生成在 actor 内执行，阅读器只保留可见区域的图片。加载失败显示重试入口。

漫画不进入文字分页器，也不拼接其他章节正文。页面使用 SwiftUI `Image`、`ScrollView` 与 `LazyVStack`。好多漫使用现有 WebKit 流程执行公开网页脚本，仅提取图片地址；不使用 WebKit 显示漫画，不绕过网站访问限制。

Windows 若增加此功能，需要扩展本地章节模型和解析结果、图片磁盘缓存及原生阅读视图。现有同步快照只交换书籍信息与阅读位置，不需要把图片地址或图片数据加入快照；`paragraphIndex` 在漫画中对应图片索引。

## 最小检查

`MangaParserTests` 使用自造 HTML / JSON 和一像素 PNG，覆盖图片顺序、广告排除、带查询参数的章节身份、完整目录、分组次序、手机域名、图片解码、缓存清理及 SwiftData 持久化。测试不依赖实时网站。

人工检查：在两端打开上述任一示例，切换两种阅读方式，前后切换章节，再返回书架重新打开，确认恢复到同一图片；缓存当前章后断网检查图片是否可读。
